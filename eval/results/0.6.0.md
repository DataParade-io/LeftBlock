# LeftBlock detection evaluation, v0.6.0

Generated by `python -m eval` (see `eval/README.md`). gitleaks 8.30.1; deep scan `openai/privacy-filter` with LeftBlock's defaults (labels secret/private_email/private_phone/private_address, threshold 0.9, built-in exclusions). Counts, rates and category names only: no values, no file contents, no dataset file paths.

## How to read the numbers

- **Unit.** One labelled line (a multi-line label such as a PEM key is one unit, hit when a finding overlaps any of its lines). True (T) and false (F) labels are scored; X (undecided) labels are excluded and counted.
- **Hit.** A detector hits a unit when one of its findings overlaps the unit's lines. Recall = TP/(TP+FN); precision = TP/(TP+FP). Intervals are Wilson 95% intervals.
- **Precision is precision on labelled lines, not a false-alarm rate.** CredData's F lines are *candidate* lines that look like credentials (chosen by scanners and heuristics, then judged by people), so they are hard negatives. A detector's precision here is much lower than its precision on arbitrary code, and it says nothing about the other 19 million lines.
- **Critical tier.** A unit is in the tier when any of its categories maps to one of: `cloud_keys`, `private_keys`, `provider_tokens`, `passwords`, `auth_headers` (mapping in `eval/tiers.py`). The generic categories (Key, Token, API, Secret, Auth, Credential) are not in the tier; they are in the "broad" tier in the JSON.

### How CredData rewrote AWS access key ids

`download_data.py` obfuscates every value to a same-shape fake. For the 213 true "AWS Client ID" rows: **0 end in `EXAMPLE` and 0 contain `example` in any case**, so the AWS documentation values that gitleaks allowlists are not used and no category is discounted for that reason. What the rewrite does do is keep the prefix and replace the tail with random letters and digits, which breaks the base32 alphabet (`A-Z2-7`) the gitleaks rule needs: 102 keep a gitleaks-matchable shape, 57 have a gitleaks prefix but a tail outside base32, and 54 carry another IAM prefix (AIDA, AROA, APKA, ...) that the gitleaks AWS rule does not target at all (0 rows have no value position). The misses on this category therefore overstate real-world misses; the row below scores only the units that still have a matchable shape.

## Caveats

- **The model may have seen CredData in training.** OpenAI's Privacy Filter model card reports a CredData split, so (c) and (d) on CredData may be optimistic; the generated corpus is the cleaner test of the deep scan.
- **Windows are not production.** The deep scan normally reads added lines of a diff. Here it reads ±5 lines around labelled lines, which is the same text with the same exclusions, but the labelled lines are over-represented compared with real diffs.
- **A repeated line is one finding.** `deep.scan` reports one finding per distinct (rule, file, line text); the harness credits every window line with identical text.
- **Critical-tier choices are judgment calls.** NKEY seeds, PASERK/PASETO tokens, OTP seeds and the generic categories are outside the tier; move them in `eval/tiers.py` if you disagree.
- **Sampling.** Critical true lines are a census. Everything else in the deep-scan sample is a weighted stratified sample; see the intervals.
